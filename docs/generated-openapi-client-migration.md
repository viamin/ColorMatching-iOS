# Generated OpenAPI client migration (issue #5)

Red-phase test plan and contract-delta record for replacing the hand-written
API layer (`iOS/Sources/ColorMatchingLPSAppCore/APIClient.swift`) with a
client generated by `swift-openapi-generator` from the OpenAPI document
published by viamin/color_matching#110.

Upstream status (verified 2026-10-31): #110 is **closed/merged**. The spec is
built with `open_api_spex` from `ColorMatchingWeb.ApiSpec` +
`ColorMatchingWeb.ApiSchemas` and served at `GET /api/v1/openapi.json`.
There is no static spec file in the upstream repo, so this app must vendor a
rendered copy (or render it from the upstream modules).

## Contract deltas: prose contract vs published spec

`docs/color-matching-api-contract.md` (prose) vs the merged upstream spec
(`ApiSchemas` + controllers, `main` as of 2026-10-31):

1. **Measurement upload response body (breaking for the app).** The prose
   contract documents no response body; the hand-written client accepted any
   2xx and ignored the body (its own tests stubbed `204`). The spec declares
   `200` with a **required** JSON body
   `MeasurementUploadResponse {capture_id, measurement_count, pair_score_count}`.
   A generated client makes `204` an `.undocumented` response — exactly the
   drift-visibility this issue wants (covered by
   `testUploadMeasurementsOperationSurfacesUndocumentedStatusAsDriftSignal`).
2. **Judgment upload response body.** Same shape of delta: spec declares `200`
   with `JudgmentUploadResponse {capture_id, judgment_count}`; prose documents
   no body.
3. **Measurement upload request loses fields.** Prose sends a top-level
   `scoring_algorithm_version` and per-measurement
   `stats {sample_count, clipping_fraction, mean, standard_deviation}`. The
   published spec declares **neither** — the server ignores them and does not
   persist stats. The generated request type will not carry them; migration
   drops them from the wire (asserted by the measurement-key set assertions in
   `APIClientTests`).
4. **`normalized_linear_rgb_median` is required per item** in the spec's
   measurement items; the hand-written model treats it as optional. The app
   must always send it.
5. **RGB values are `RgbPayload` anyOf** (numeric array, `{r,g,b}` object, or
   string) in the spec — the app keeps sending the `{r,g,b}` object form.
6. **`PairScoreRequest`** requires `pair_id` + `algorithm_version` plus anyOf
   `score`/`similarity`/`distance`; the app's similarity+distance payload
   satisfies it.
7. **Manifest response under-declared (blocking gap).** The spec's
   `TestSheetManifest` declares only `schema_version` (enum
   `lps-sheet-manifest/v1`), `sheet_id`, and
   `capture_profile.scoring_algorithm_version` (enum `lps-distance-v1`), but
   the server actually returns the full manifest the app needs (`page`,
   `registration_markers`, `printer_profile`, full `capture_profile`,
   `patches`, `pairs`, `sheet_version`, `manifest_url`, `created_at`). The
   vendored spec must extend the manifest declaration (required fields per the
   assertions in `assertFullManifestDecoded`); recommend upstreaming the
   extension so the published spec matches reality.
8. **Ranked results under-declared (blocking gap).** The spec's
   `RankedResults` declares only `schema_version` (enum — note the new version
   string `lps-ranked-results/v1`, absent from the prose contract) and
   `sheet_id`; the server returns `printer_profile`, `capture_count`,
   `latest_capture_at`, `earliest_capture_at`, `scoring_algorithm_versions`,
   and dense `results[]` rows (rank, pair_id, scoring_algorithm_version,
   row/col, source_colors{color_a_hex,color_b_hex}, score{average, latest,
   minimum, maximum, capture_count, sample_count, algorithm_versions},
   current_judgment, current_judgment_observed_at, observation_count,
   latest_observation, per-row capture window). The vendored spec must declare
   the rows the app reads (pinned by `testFetchRankedResults…` /
   `testRankedResultsOperation…`).
9. **`printer_profile` shape differs from prose.** Prose: `{id, name, paper,
   ink, settings}`. Server manifest payload: `{printer_make_model, paper_type,
   ink_type, icc_profile, print_settings, driver_name, driver_version,
   calibration_date, calibration_version, notes}` — no `id`.
10. **IDs are numeric strings.** `capture_id` responses return
    `Integer.to_string(id)` (e.g. `"12"`), and capture path params are cast to
    integers server-side. Prose examples imply prefixed IDs (`"capture_123"`).
    Use real numeric-string IDs in tests/stubs.
11. **Patch ids are composite** (`"pair_1#first"`), not `"patch_1"` as prose
    implies.
12. **`manifest_url` is server-built** via Phoenix verified routes; it may be
    relative or absolute depending on endpoint host configuration (prose
    shows absolute). Treat as opaque string.
13. **`iso` is an integer** in the spec (the hand-written Swift model used
    `Float`); `exposure_duration_seconds` is a number. The spec's flat capture
    form uses `exposure_duration` (no `_seconds`) and `rejection_reasons` —
    the app uses the nested `metadata` + `quality` form, which the spec
    accepts via `anyOf` and which matches the prose contract.
14. **Recent sheets `title` is always `null` today** (server hardcodes nil);
    spec keeps it required-but-nullable. Decode as `String?`.
15. **Security.** The spec declares `bearerAuth` (http bearer) on all
    sheet/capture operations — matches the prose contract. Generated clients
    do not inject credentials themselves; the app must add an
    auth-injecting transport/middleware (asserted via the `Authorization`
    header checks in `APIClientTests`).
16. **Typed error shape.** `401/404/422` responses are
    `ApiErrorResponse {errors: object | [{detail, source.pointer}]}`; the
    generated client surfaces them as typed output cases
    (`.unauthorized`, `.notFound`, `.unprocessableEntity`).

## Endpoint gaps

- App surfaces with **no upstream declaration depth**: manifest and ranked
  results (see deltas 7–8). Must be fixed in the vendored document; upstream
  PR recommended.
- Spec contains routes the app does not use (no action): `/api/v1/printer_profiles`
  (+ `/colors`, `/metamer_pairs`), `/api/v1/palettes`, `/api/v1/colors`,
  `/api/illuminant_measurements` (+ `/bulk`), `/api/multi_image_mapping`,
  and the self-describing `/api/v1/openapi.json`.
- The app previously had **no ranked-results client surface at all**; the
  migration adds `APIClient.fetchRankedResults(baseURL:sheetID:)`.

## Target architecture for the implementation run

- Package deps: `apple/swift-openapi-generator` (build plugin),
  `apple/swift-openapi-runtime`, `apple/swift-openapi-urlsession`
  (current 1.x line; the runtime 1.13+ HTTPTypes-based transport API is what
  the tests stub).
- New target `ColorMatchingOpenAPI` with
  `openapi.yaml` (vendored, extended per deltas 7–8) +
  `openapi-generator-config.yaml`, using the `OpenAPIGenerator` plugin.
- `ColorMatchingLPSAppCore.APIClient` keeps its initializer
  (`token:session:`) and method names, but its parameter/return types move to
  generated `Components.Schemas` types:

  ```swift
  fetchManifest(baseURL:sheetCode:) async throws -> Components.Schemas.TestSheetManifest
  fetchRecentSheets(baseURL:) async throws -> [Components.Schemas.RecentSheetsResponse.sheetsPayload]
  fetchRankedResults(baseURL:sheetID:) async throws -> Components.Schemas.RankedResults   // new
  createCapture(sheetID:baseURL:metadata:quality:) async throws -> Components.Schemas.CaptureCreatedResponse
  uploadMeasurements(captureID:baseURL:measurements:[PatchMeasurement], scores:[PairScore]) async throws -> Components.Schemas.MeasurementUploadResponse
  uploadJudgments(captureID:baseURL:judgments:[Components.Schemas.JudgmentUploadRequest.judgmentsPayload]) async throws -> Components.Schemas.JudgmentUploadResponse
  ```

  `MeasurementCore` models (`PatchMeasurement`, `PairScore`, `ChannelStats`,
  `CaptureQuality`-adjacent analysis types) are purely client-side and stay
  as-is; the façade maps them into generated request types. Undocumented
  response statuses (e.g. `204` from an older server) must surface as thrown
  errors, not silent success.

## Generated naming ledger

Derived from the as-published operationIds (open_api_spex emits
`"ColorMatchingWeb.<Controller>.<action>"`; dots map to underscores under the
generator's idiomatic naming):

| Operation | operationId | Client method |
|---|---|---|
| GET manifest | `ColorMatchingWeb.TestSheetController.manifest` | `colorMatchingWeb_TestSheetController_manifest` |
| GET recent | `ColorMatchingWeb.TestSheetController.recent` | `colorMatchingWeb_TestSheetController_recent` |
| GET ranked results | `ColorMatchingWeb.TestSheetController.ranked_results` | `colorMatchingWeb_TestSheetController_ranked_results` |
| POST capture | `ColorMatchingWeb.CaptureController.create` | `colorMatchingWeb_CaptureController_create` |
| POST measurements | `ColorMatchingWeb.CaptureController.upload_measurements` | `colorMatchingWeb_CaptureController_upload_measurements` |
| POST judgments | `ColorMatchingWeb.CaptureController.upload_judgments` | `colorMatchingWeb_CaptureController_upload_judgments` |

Generated inits order arguments by JSON property declaration order; the
vendored document (rendered from Elixir maps) orders properties
alphabetically, so test constructions pass arguments in that order
(`appVersion`, `deviceModel`, … `whiteBalanceGains`; `judgment` before
`pairId`; `metadata` before `quality`). If the vendoring step normalizes
operationIds or reorders properties, only the argument order and the method
names in the tests need updating — each is referenced in exactly one place
per call site.

## Phase note (tests-only PR)

This run only adds tests + this document. The suites are intentionally red:

- The `ColorMatchingOpenAPI` module does not exist yet, so
  `iOS/Tests/ColorMatchingLPSAppTests` does not compile until the
  implementation run lands AC-1/AC-2. That compile failure is the missing-
  behavior signal for the generated-client criteria.
- `APIClientTests.swift` was rewritten from the hand-written-client tests
  (deleted with justification: their subject — the hand-written
  request/response models — is exactly what this issue removes; their
  surviving wire assertions were carried into the new tests, e.g. bearer
  token, snake_case bodies, capture/judgment paths).
- No Swift toolchain exists in the authoring container, so `swift test`
  cannot be executed here at all; CI (`macos-latest`, `swift test`) is the
  executor of record once implementation lands.
- Exit criterion: `swift test --disable-sandbox` green with generated types
  wired in, and `MeasurementCoreTests` untouched.
