## Upstream evidence and known gap

`viamin/color_matching#110` was delivered by [viamin/color_matching#113](https://github.com/viamin/color_matching/pull/113) on 2026-10-30. Its changed router exposes `GET /api/v1/openapi.json`; the spec is generated by the Phoenix application rather than committed as a raw file.

The prose contract already describes five request paths. It describes `ranked_results` only narratively, without a response schema. The real OpenAPI document is therefore required before claiming whether its operation ID, request/response schemas, enums, nullable fields, and error responses differ. The migration test deliberately requires that endpoint, making this existing prose gap visible during implementation.

## Implementation handoff

1. Fetch the published JSON response and commit it as `iOS/OpenAPI/openapi.json`.
2. Add the generator/runtime packages and `OpenAPIGenerator` build-tool plugin; generate the `ColorMatchingAPI` module.
3. Adapt `APIClient` to generated operations and remove its transport Codable declarations. Preserve measurement-only domain types in `MeasurementCore`.
4. Extend the existing `MockURLProtocol` tests with fixture responses for manifest, recent sheets, and ranked results, invoking the generated-backed facade for every required path.
5. Record the actual spec-versus-prose deltas in the implementation PR body and update `tmp/paid-agent-verification.json` with the resulting test output.
