# OpenAPI Generated Client — Implementation & Verification Plan

Plan for replacing the hand-written API layer with a client generated by
`swift-openapi-generator` (issue #5). The tests landed in this PR are the
red phase: they reference the `ColorMatchingOpenAPI` module and the
generated type surface defined below, so they do not compile until the
implementation run lands the package manifest + vendored spec. No live
server is required — every test stubs HTTP at the transport level.

## End state being pinned by the tests

### Package manifest (implementation run)

`iOS/Package.swift` gains:

```swift
// dependencies
.package(url: "https://github.com/apple/swift-openapi-generator", from: "1.14.0"),
.package(url: "https://github.com/apple/swift-openapi-runtime", from: "1.13.0"),
// target
.target(
    name: "ColorMatchingOpenAPI",
    dependencies: [
        .product(name: "OpenAPIRuntime", package: "swift-openapi-runtime"),
        .product(name: "HTTPTypes", package: "swift-http-types")
    ],
    plugins: [.plugin(name: "OpenAPIGenerator", package: "swift-openapi-generator")]
),
```

The vendored document is `docs/color-matching-openapi-v1.yaml`, copied
verbatim to `iOS/Sources/ColorMatchingOpenAPI/openapi.yaml` (the
generator's default document path). `ColorMatchingLPSAppCore` and
`ColorMatchingLPSApp` depend on `ColorMatchingOpenAPI`; the test target
`ColorMatchingLPSAppTests` also gains `ColorMatchingOpenAPI`,
`OpenAPIRuntime`, and `HTTPTypes` product dependencies (the
generated-client tests import all three).

### Generated surface (deterministic; derived from the vendored spec)

`swift-openapi-generator` (SOAR-0013 idiomatic naming) turns each
operationId into a method name: leading char lowercased, `_ - / + space`
removed with the next word capitalized, `.` replaced by `_`:

| Operation (operationId) | Generated method |
|---|---|
| `ColorMatchingWeb.TestSheetController.manifest` | `colorMatchingWeb_TestSheetController_manifest(_:)` |
| `ColorMatchingWeb.TestSheetController.recent` | `colorMatchingWeb_TestSheetController_recent()` |
| `ColorMatchingWeb.TestSheetController.ranked_results` | `colorMatchingWeb_TestSheetController_rankedResults(_:)` |
| `ColorMatchingWeb.CaptureController.create` | `colorMatchingWeb_CaptureController_create(_:)` |
| `ColorMatchingWeb.CaptureController.upload_measurements` | `colorMatchingWeb_CaptureController_uploadMeasurements(_:)` |
| `ColorMatchingWeb.CaptureController.upload_judgments` | `colorMatchingWeb_CaptureController_uploadJudgments(_:)` |

Path parameters are sanitized like members — underscores count as word
separators, so `sheet_id` → `Input.path.sheetId` and `capture_id` →
`Input.path.captureId`. Schema properties become lowerCamelCase the same
way (`schema_version` → `schemaVersion`, with a CodingKey raw value
preserving the wire key). Status codes map to Output cases: 200 → `.ok`,
201 → `.created`, 401 → `.unauthorized`, 404 → `.notFound`, 422 →
`.unprocessableContent`.

### App-facing facade (kept in `ColorMatchingLPSAppCore`)

`APIClient` stays the app's entry point (SwiftUI views keep calling it),
reimplemented on top of the generated `Client` with a
`URLSessionTransport`. Purely client-side models stay as-is
(`MeasurementCore`'s `RGB`, `ChannelStats`, `PatchMeasurement`,
`PairScore`, `CaptureQuality`, and the full `SheetManifest` geometry used
by `SheetAnalyzer`). Hand-written API models (`APIClient.CaptureMetadata`,
`WhiteBalanceGains`, `RecentSheet`, `PairJudgment`,
`CaptureSessionResponse`, the private upload request DTOs) are deleted;
generated types replace them. Bearer auth is injected via
`URLSessionConfiguration.httpAdditionalHeaders` (the generated client does
not apply security schemes itself).

Facade surface exercised by `OpenAPIFacadeTests`:

```swift
APIClient(token: String?, session: URLSession) // session feeds URLSessionTransport
// fetchManifest(from:) (direct manifest URL) also stays, backed by the same generated operation
func fetchManifest(baseURL: URL, sheetCode: String) async throws -> Components.Schemas.TestSheetManifest
func fetchRecentSheets(baseURL: URL) async throws -> [Components.Schemas.RecentSheet]
func createCapture(sheetID: String, baseURL: URL,
                   metadata: Components.Schemas.CaptureMetadata,
                   quality: MeasurementCore.CaptureQuality) async throws -> Components.Schemas.CaptureCreatedResponse
func uploadMeasurements(captureID: String, baseURL: URL,
                        measurements: [PatchMeasurement], scores: [PairScore]) async throws -> Components.Schemas.MeasurementUploadResponse
func uploadJudgments(captureID: String, baseURL: URL,
                     judgments: [Components.Schemas.PairJudgment]) async throws -> Components.Schemas.JudgmentUploadResponse
func fetchRankedResults(sheetID: String, baseURL: URL) async throws -> Components.Schemas.RankedResults
```

Wire-behavior changes the facade must adopt (deltas D1–D8 in
`docs/color-matching-openapi-deltas.md`): uploads return `200` JSON with
counts; measurement payloads carry no `stats` block and no top-level
`scoring_algorithm_version`; `iso` is integral; error statuses surface as
typed failures rather than a blanket `badStatus`.

## Test architecture (this PR)

All new tests live in `iOS/Tests/ColorMatchingLPSAppTests/` and run with
`swift test --disable-sandbox` on macOS CI (and `swift test` in the
existing GitHub Actions workflow). No network access is needed:

1. **`OpenAPISpecContractTests.swift`** — guards the vendored
   `openapi.yaml`: the six app operations keep their upstream paths,
   operationIds, and status codes; the gap-filled schema fields the app
   depends on stay present. Any regeneration drift shows up here first.
2. **`OpenAPIGeneratedClientTests.swift`** — drives the generated
   `ColorMatchingOpenAPI.Client` directly through a stubbed
   `ClientTransport` (OpenAPIRuntime), one operation per test: request
   path/method/body wire assertions and response decoding into generated
   types, including `.notFound` / `.unprocessableContent` branches.
3. **`OpenAPIFacadeTests.swift`** — drives `APIClient` end-to-end through
   `URLSession` + a stubbed `URLProtocol` (the pattern already used by
   `APIClientTests`): bearer header, spec-conformant upload bodies,
   response-count decoding, and the new ranked-results surface.

Existing `APIClientTests.swift` continues to pin today's behavior until
the implementation run replaces the hand-written DTOs; the implementation
run updates it alongside the facade change.

## Acceptance criteria → verification mapping

| AC (from issue #5) | Verification | Where |
|---|---|---|
| AC-1 deps + vendored spec in package | Inspectable manifest change (implementation run) + spec-contract test on the vendored document | `OpenAPISpecContractTests` |
| AC-2 client generated for all six surfaces | Unit test per operation against stubbed transport | `OpenAPIGeneratedClientTests` (6 ops) |
| AC-3 hand-written API models replaced; client-side models kept | Facade tests through generated types + code review of model deletion | `OpenAPIFacadeTests`; implementation diff |
| AC-4 Swift tests against local stubbed responses, no live server | All new tests stub `ClientTransport`/`URLProtocol`; no server needed | all three files |
| AC-5 PR description records contract deltas + gaps | Delta analysis document feeding the PR body | `docs/color-matching-openapi-deltas.md` |

Red-phase status at this commit: the tests intentionally fail to build
because `ColorMatchingOpenAPI` / the facade evolution do not exist yet
(compile-time missing-behavior failure, the Swift analogue of a red
assertion). `swift test` cannot be executed in this container (no Swift
toolchain); macOS CI executes the suite.

## Verification commands

```bash
cd iOS
swift test --disable-sandbox        # exit criteria for the implementation run
```

Offline verification performed in this container (no Swift toolchain
available; macOS CI executes the Swift suite):

```bash
python -m pip install pyyaml openapi-spec-validator
python -c "import yaml; from openapi_spec_validator import validate; validate(yaml.safe_load(open('docs/color-matching-openapi-v1.yaml')))"
# => VALID OpenAPI 3.0.3

python -c "..."  # validate every JSON fixture used by the Swift tests
#    against its schema in the vendored spec (TestSheetManifest,
#    RankedResults, RecentSheetsResponse, MeasurementUploadResponse,
#    JudgmentUploadResponse, ApiErrorResponse, CaptureCreatedResponse,
#    CaptureMetadata, CaptureRequest, MeasurementUploadRequest,
#    JudgmentUploadRequest)
# => all fixtures conform

python -c "..."  # replay the OpenAPISpecContractTests string assertions
#    against the vendored YAML
# => all assertions pass
```

So: the vendored document is a well-formed OpenAPI 3.0.3 spec, every
stubbed response used by the new tests conforms to it, and the spec
contract checks pass. The Swift files themselves are red phase — they
reference `ColorMatchingOpenAPI`, which the implementation run adds.
