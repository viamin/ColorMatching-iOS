# Generated OpenAPI Client — Test Plan And Implementation Contract

Issue #5 replaces the hand-written API layer (`iOS/Sources/ColorMatchingLPSAppCore/APIClient.swift`,
prose contract in [color-matching-api-contract.md](color-matching-api-contract.md)) with a client
generated by `apple/swift-openapi-generator` from the OpenAPI document published by
viamin/color_matching#110. This document maps every acceptance criterion to its smallest credible
verification and records the exact contract the tests expect the implementation run to satisfy.

## Implementation contract (what the tests pin)

1. **Vendored spec.** The published OpenAPI document is vendored as JSON at
   `iOS/OpenAPI/color-matching-api.json`. JSON is required because the coverage tests parse it with
   `JSONSerialization`. Convert with `jq`/`yaml2json` if color_matching#110 publishes YAML.
2. **Package wiring.** `Package.swift` declares the `apple/swift-openapi-generator` and
   `apple/swift-openapi-runtime` products and applies the `GenerateOpenAPIClient` plugin to the
   client target, with `--input-path OpenAPI/color-matching-api.json`. `swift test --disable-sandbox`
   (already the documented command in `README.md`) is how the plugin build runs locally and in CI.
3. **Generated output.** The plugin's default output directory `Sources/**/OpenAPIGenerated/` must
   exist and contain Swift sources; the tests assert this so a misconfigured plugin cannot pass
   silently.
4. **Stable `APIClient` surface.** The app calls `APIClient` from `ContentView`; the swap happens
   inside `APIClient` (URL building, encoding, decoding replaced by the generated client over a
   `URLSession`-backed transport). Method signatures and the `MeasurementCore` client-side models
   (`SheetManifest`, `Patch`, `PairManifest`, `PatchMeasurement`, `PairScore`, `CaptureQuality`,
   …) stay as-is; generated types are mapped to/from them.
5. **New ranked-results surface.** `APIClient` gains exactly:
   ```swift
   public func fetchRankedResults(sheetID: String, baseURL: URL) async throws -> [PairScore]
   ```
   issuing `GET /api/v1/test_sheets/{sheet_id}/ranked_results` with the bearer token when present.
   The test reaches the method through a file-private `RankedResultsFetching` protocol whose default
   implementation throws; once `APIClient` declares the real method it automatically becomes the
   protocol witness, so the same test flips from red to green with no test-side edits.
6. **Wire compatibility.** Paths (`/api/v1/test_sheets/{id}/manifest`, `/test_sheets/recent`,
   `/test_sheets/{id}/captures`, `/captures/{id}/measurements`, `/captures/{id}/judgments`,
   `/test_sheets/{id}/ranked_results`), `Authorization: Bearer …` headers, snake_case JSON bodies,
   and non-2xx → thrown error behavior are pinned by `APIClientWireContractTests` and
   `APIClientTests` and must not change.
7. **Ranked-results fixture is provisional.** The prose contract gives no ranked-results JSON
   example, so the wire test stubs `{"results": [{pair_id, distance, similarity, algorithm_version}]}`.
   If the published spec shapes the response differently, adjust the stub fixture and the
   generated→`PairScore` mapping together in the implementation PR and record the shape as a
   contract delta. `OpenAPIClientGenerationTests/testRankedResultsResponseContainsPairScores`
   tolerates any wrapper property as long as some array item declares `pair_id` plus
   `distance`/`similarity`/`algorithm_version`.

## Recording contract deltas

Run the `OpenAPIClientGenerationTests` suite against the vendored spec. Every failing assertion names
the exact prose-contract expectation that the published spec does not meet (missing path, missing
method, missing operationId, missing property). The implementation PR description must contain a
table of those deltas — prose contract vs published spec — plus any endpoint gaps discovered, and
state how each was reconciled (spec regenerated on the Phoenix side, mapping added client-side, or
test fixture adjusted per item 7 above). Deliberate decisions, not silent fixture edits.

## Environment note

The authoring container for this tests-only change has no Swift toolchain, so the suite was not
executed locally. CI (`.github/workflows/ci.yml`, macOS, `swift test`) is the executor; the table
above records the expected red/green split at this commit.
