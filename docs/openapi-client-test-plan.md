# OpenAPI generated-client test plan (issue #5)

Test-writing-run deliverable for replacing the hand-written API layer with a
generated OpenAPI Swift client. This document pins the contract the committed
tests expect; the implementation run must make `swift test --disable-sandbox`
green against it.

## Expected package layout

```
iOS/
  OpenAPI/
    color-matching-openapi.json        # vendored spec (fetched from GET /api/v1/openapi.json)
  Sources/
    ColorMatchingOpenAPI/
      openapi.yaml                     # or the vendored JSON directly
      openapi-generator-config.yaml    # mode: types, generate: client
      (sources generated by swift-openapi-generator plugin)
  Tests/
    ColorMatchingOpenAPITests/         # this run's new test target
      TestSupport.swift
      GeneratedClientTests.swift
      APIClientFacadeTests.swift
```

`Package.swift` additions (implementation run):

- package dependencies: `swift-openapi-generator` (plugin),
  `swift-openapi-runtime`, `swift-openapi-urlsession`
- `.target(name: "ColorMatchingOpenAPI", dependencies: [OpenAPIRuntime],
  plugins: [OpenAPIGenerator])`
- `ColorMatchingLPSAppCore` gains a dependency on `ColorMatchingOpenAPI`
- `.testTarget(name: "ColorMatchingOpenAPITests", dependencies:
  ["ColorMatchingLPSAppCore", "ColorMatchingOpenAPI", OpenAPIRuntime,
  OpenAPIURLSession])`

## Vendoring rules

1. Fetch the document from a running `color_matching` at
   `GET /api/v1/openapi.json` (issue viamin/color_matching#110, closed: spec
   is live) and vendor it verbatim as the baseline.
2. Rename operationIds for usable generated method names (OpenApiSpex derives
   controller-qualified ids):

   | Published operationId | Vendored operationId | Generated method |
   | --- | --- | --- |
   | `ColorMatchingWeb.TestSheetController.manifest` | `fetchTestSheetManifest` | `fetchTestSheetManifest` |
   | `ColorMatchingWeb.TestSheetController.recent` | `listRecentTestSheets` | `listRecentSheets` |
   | `ColorMatchingWeb.TestSheetController.ranked_results` | `fetchRankedResults` | `fetchRankedResults` |
   | `ColorMatchingWeb.CaptureController.create` | `createCapture` | `createCapture` |
   | `ColorMatchingWeb.CaptureController.upload_measurements` | `uploadMeasurements` | `uploadMeasurements` |
   | `ColorMatchingWeb.CaptureController.upload_judgments` | `uploadJudgments` | `uploadJudgments` |

3. Widen the Manifest schema to the rendered shape (delta #1 in
   `docs/openapi-contract-deltas.md`): add `sheet_version`, `manifest_url`,
   `created_at`, `page`, `registration_markers`, `printer_profile` (rendered
   key names, delta #2), `patches`, `pairs` — all optional; keep
   `schema_version`, `sheet_id`, `capture_profile` required. Mark widened
   fields with a `description` noting they document renderer behavior the
   upstream spec under-documents.
4. Every vendored divergence from the published document must appear in
   `docs/openapi-contract-deltas.md`.

## Generated surface the tests pin

- Module `ColorMatchingOpenAPI`; client type `ColorMatchingOpenAPI.Client`
  initialized with `serverURL:` + `transport:` (`URLSessionTransport`).
- Named schema types under `Components.Schemas`: `TestSheetManifest`,
  `RecentSheetsResponse`, `RankedResults`, `CaptureRequest`,
  `CaptureMetadata`, `CaptureCreatedResponse`, `MeasurementUploadRequest`,
  `MeasurementUploadResponse`, `JudgmentUploadRequest`,
  `JudgmentUploadResponse`, `ApiErrorResponse` (titles from the published
  spec).
- JSON keys stay snake_case on the wire (generated CodingKeys); Swift
  properties are lowerCamelCase (`sheet_id` → `sheetId`,
  `capture_id` → `captureId`, `measurement_count` → `measurementCount`).
- Response wrappers: `.ok` / `.created` / `.notFound` / `.unauthorized` /
  `.unprocessableEntity` / `.undocumented(statusCode:payload:)` with `.json`
  body cases; stubbed responses must carry `Content-Type: application/json`.

## Facade contract (`ColorMatchingLPSAppCore.APIClient`)

The facade keeps ContentView's call sites intact while being backed by the
generated client:

- `init(token: String?, session: URLSession = .shared)` — unchanged; token is
  attached as `Authorization: Bearer` (via transport middleware).
- `fetchManifest(from: URL)` / `fetchManifest(baseURL:sheetCode:)` still
  returns MeasurementCore's client-side `SheetManifest` (the published spec
  under-documents sheet geometry; the model stays client-side per the issue).
- `fetchRecentSheets(baseURL:)` returns the generated recent-sheet items.
- `fetchRankedResults(sheetID:baseURL:)` — new — returns the generated
  `RankedResults` schema value.
- `createCapture(sheetID:baseURL:metadata:quality:)` returns the generated
  `CaptureCreatedResponse`.
- `uploadMeasurements(captureID:baseURL:measurements:scores:)` returns the
  generated `MeasurementUploadResponse` (previously `Void`).
- `uploadJudgments(captureID:baseURL:judgments:)` returns the generated
  `JudgmentUploadResponse` (previously `Void`).
- Wire behavior preserved: nested `{metadata, quality}` capture payload,
  per-measurement `stats`, top-level `scoring_algorithm_version`,
  object-form RGB medians, snake_case keys.

### Typed errors

`APIError` becomes `Equatable` with:

```swift
case unauthorized(detail: String?)
case notFound(detail: String?)
case unprocessableEntity(detail: String?)
case unexpectedStatus(Int)
```

`detail` is `errors.detail` when the body's `errors` is an object with a
`detail` string, else `nil`. `.undocumented` responses map to
`.unexpectedStatus(code)`; `.badStatus` is removed.

### Model replacement scope

Removed (replaced by generated types): `CaptureSessionResponse`,
`RecentSheet`, `RecentSheetsResponse`, `CreateCaptureRequest`,
`MeasurementUploadRequest`, `MeasurementUpload`, `MeasurementStatsUpload`,
`JudgmentUploadRequest` (hand-written Codable payload models in
`APIClient.swift`).

Kept (client-side, not fully covered by the spec): `SheetManifest` and
MeasurementCore models (`PatchMeasurement`, `PairScore`, `ChannelStats`,
`CaptureQuality`, `CaptureRejection`), `CaptureMetadata` /
`WhiteBalanceGains` (camera domain values), `PairJudgment` (app domain value);
the facade converts these into generated request payloads.

`iOS/Tests/ColorMatchingLPSAppTests/APIClientTests.swift` predates this
contract (e.g. asserts `response.captureID`, Void uploads); the
implementation run updates it to the facade contract above or folds it into
`ColorMatchingOpenAPITests`.

## Acceptance criteria → verification mapping

| ID | Criterion | Verification | Evidence |
| --- | --- | --- | --- |
| AC-1 | swift-openapi-generator + runtime in package; spec fetched/vendored | Compile-time: tests import `ColorMatchingOpenAPI` / `OpenAPIRuntime` / `OpenAPIURLSession` and build the generated client | `iOS/Tests/ColorMatchingOpenAPITests/GeneratedClientTests.swift` |
| AC-2 | Client generated for manifest, recent sheets, capture creation, measurement upload, judgment upload, ranked results | Focused unit tests per operation against stubbed responses | `GeneratedClientTests.swift` (6 operations), `APIClientFacadeTests.swift` |
| AC-3 | Hand-written API models replaced; client-side models kept | Compile-time wiring via facade return types + kept `SheetManifest` mapping | `APIClientFacadeTests.swift` (`testFetchManifestBySheetCodeReturnsFullClientSideManifest`, generated-type results on uploads/recent/ranked) |
| AC-4 | Swift tests vs stubbed responses, no live server | All new tests stub via `StubbedURLProtocol`; no network | `iOS/Tests/ColorMatchingOpenAPITests/TestSupport.swift` |
| AC-5 | PR description records contract deltas + endpoint gaps | Human/external: analysis committed as PR-body source | `docs/openapi-contract-deltas.md` |
| EC-1 | `swift test --disable-sandbox` green with generated types wired | Implementation-run exit check; not runnable in the test-writing environment (no Swift toolchain installed) | Recorded in run evidence |
