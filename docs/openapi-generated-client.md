# Generated OpenAPI client for the `color_matching` API

Status: **tests-first (red phase)**. This document records the contract the tests in
`iOS/Tests/ColorMatchingLPSAppTests/` expect, the deltas found between
`docs/color-matching-api-contract.md` (the prose contract) and the published
OpenAPI spec, and the exact wiring the implementation run must land. The PR
description for the implementation PR should carry the delta and gap tables
below verbatim.

## Upstream dependency

`viamin/color_matching#110` is done: the Phoenix app publishes an OpenAPI 3.0
spec at `GET /api/v1/openapi.json` (merged in upstream PR #113; inspected at
upstream SHA `14320c33f93258a331cf17af7323ce9035c8a44d`, 2026-10-30). The spec
is generated by `open_api_spex` from `ColorMatchingWeb.ApiSpec` + the
controller specs, and enforced upstream by Schemathesis and an oasdiff
breaking-change gate.

## Deliverable wiring (implementation run)

1. `iOS/Package.swift`:

   - packages: `swift-openapi-generator` (build plugin) and
     `swift-openapi-runtime` (product `OpenAPIRuntime`).
   - new target `GeneratedAPIClient` depending on `OpenAPIRuntime` with
     `plugins: [.plugin(name: "OpenAPIGenerator", package: "swift-openapi-generator")]`
     and `resources: [.process("openapi.json")]`.
   - `ColorMatchingLPSAppTests` gains dependencies on `GeneratedAPIClient` and
     the `OpenAPIRuntime` product.
   - `ColorMatchingLPSAppCore` depends on `GeneratedAPIClient` when the
     hand-written `APIClient` is rewired onto the generated `Client`.

2. `iOS/Sources/GeneratedAPIClient/`:

   - `openapi.json` — the vendored document (see normalizations below).
   - `openapi-generator-config.yaml` — `namingStrategy: idiomatic`. The tests
     rely on idiomatic names (`sheetId`, `captureProfile`, enum case
     `lpsDistanceV1`, method `getTestSheetManifest`, …). Without this file the
     generator defaults to `defensive` names (`sheet_id`,
     `lps_hyphen_distance_hyphen_v1`) and the tests will not compile.
   - `GeneratedAPIClient.swift` — re-export + bearer middleware:

     ```swift
     import OpenAPIRuntime
     @_exported import OpenAPIGeneratedTypes

     public struct BearerAuthMiddleware: ClientMiddleware {
         public var token: String
         public init(token: String) { self.token = token }
         public func intercept(
             _ request: HTTPRequest, body: HTTPBody?, baseURL: URL, operationID: String,
             next: @Sendable (HTTPRequest, HTTPBody?, URL) async throws -> (HTTPResponse, HTTPBody?)
         ) async throws -> (HTTPResponse, HTTPBody?) {
             var request = request
             request.headerFields[.authorization] = "Bearer \(token)"
             return try await next(request, body, baseURL)
         }
     }
     ```

3. Rewire `ColorMatchingLPSAppCore/APIClient` onto the generated `Client`
   (with `URLSessionTransport` and `BearerAuthMiddleware`), mapping generated
   types to/from the client-side `MeasurementCore` models. Keep
   `APIClientTests` green; they pin paths, payloads, and bearer auth on the
   wire.

## Vendoring rules

Fetch from a running `color_matching` (or the upstream CI artifact):

```bash
curl -s http://localhost:4000/api/v1/openapi.json \
  > iOS/Sources/GeneratedAPIClient/openapi.json
```

Then apply the recorded normalizations (below), record the upstream SHA the
document was fetched from in this file, and re-run
`swift test --disable-sandbox`. Drift re-check is a plain diff against a fresh
fetch (normalizations are reproducible).

### Normalization 1 — operationIds

`open_api_spex` derives operationIds as `<ControllerModule>.<action>`
(e.g. `ColorMatchingWeb.TestSheetController.manifest`), which produce poor
Swift method names. The vendored document assigns clean operationIds; schemas
and paths stay byte-identical to the served document:

| Path | Method | operationId |
| --- | --- | --- |
| `/api/v1/test_sheets/{sheet_id}/manifest` | GET | `getTestSheetManifest` |
| `/api/v1/test_sheets/recent` | GET | `listRecentTestSheets` |
| `/api/v1/test_sheets/{sheet_id}/captures` | POST | `createCapture` |
| `/api/v1/captures/{capture_id}/measurements` | POST | `uploadMeasurements` |
| `/api/v1/captures/{capture_id}/judgments` | POST | `uploadJudgments` |
| `/api/v1/test_sheets/{sheet_id}/ranked_results` | GET | `getRankedResults` |

Paths the app does not use (printer profiles, palettes, colors, metamer
pairs, illuminant measurements, multi-image mapping) stay in the vendored
document untouched; generating extra client methods is harmless and keeps the
diff-to-upstream minimal.

### Normalization 2 — `CaptureRequest`

As published, `CaptureRequest` mixes `properties` with a sibling `anyOf`
(flat legacy form vs `metadata`/`quality` nested form). OpenAPI 3.0 parsers
(including OpenAPIKit, which swift-openapi-generator uses) drop sibling
`properties` for combinator schemas, so the published schema is not consumable
by the generator: the flat fields vanish and the generated type is a useless
`value1`/`value2` container pair. The vendored document keeps only the nested
form the iOS app sends:

```json
{
  "type": "object",
  "properties": {
    "metadata": { "$ref": "#/components/schemas/CaptureMetadata" },
    "quality": {
      "type": "object",
      "properties": {
        "detected_marker_count": { "type": "integer", "minimum": 0 },
        "blur_score": { "type": "number", "minimum": 0 },
        "rejections": { "type": "array", "items": { "type": "string" } }
      }
    }
  },
  "required": ["metadata", "quality"]
}
```

### Normalization 3 — `PairScoreRequest`

Same defect as `CaptureRequest`: `properties` (`pair_id`, `algorithm_version`,
`score`/`similarity`/`distance`) sit next to a sibling `anyOf`
(`required: [score] | [similarity] | [distance]`). The vendored document
flattens to one object with `required: ["pair_id", "algorithm_version"]` and
optional `score`, `similarity`, `distance`.

## Contract deltas: prose contract vs published spec

Source of truth compared: `docs/color-matching-api-contract.md` vs the schemas
in `lib/color_matching_web/api_schemas.ex` + rendering in
`lib/color_matching_web/controllers/test_sheet_json.ex` (upstream SHA above).

| # | Surface | Prose contract | Published spec | Consequence |
| --- | --- | --- | --- | --- |
| 1 | Manifest response | Full manifest: `sheet_version`, `manifest_url`, `created_at`, `page`, `registration_markers`, `printer_profile`, `patches`, `pairs` | `TestSheetManifest` documents only `schema_version` (enum `lps-sheet-manifest/v1`), `sheet_id`, `capture_profile.scoring_algorithm_version` (enum `lps-distance-v1`). The wire JSON still carries the full manifest (asserted upstream), but those fields are **undocumented** | Generated client types only the envelope. Undocumented fields are dropped at decode. Sheet analysis must keep decoding the full manifest from the raw wire shape (client-side model), or upstream must document the rest. Gap pinned by `testManifestSchemaDocumentsOnlyTheVersionedEnvelope` |
| 2 | Recent sheets | `{sheets: [{sheet_id, manifest_url, title\|null}]}` | Same; `title` required+nullable; `sheet_id` is the sheet **lookup code** | No action; generated type matches |
| 3 | Capture create request | Nested `{metadata: {...}, quality: {...}}` only | Accepts nested **or** flat form via sibling `anyOf`; flat form names the exposure `exposure_duration` (prose: `exposure_duration_seconds`) and rejections `rejection_reasons` (prose: `quality.rejections`); `iso` typed `integer` (app model: `Float`) | App keeps the nested form. Vendored schema normalized (Normalization 2). `iso` must be sent as an integer |
| 4 | Capture create response | `{"capture_id": "..."}` | `201` + `{"capture_id": "..."}`; `capture_id` is the DB integer as a string | Matches |
| 5 | Measurement upload request | Top-level `scoring_algorithm_version`; measurements carry `stats` (`sample_count`, `clipping_fraction`, `mean`, `standard_deviation`); RGB medians as `{r,g,b}` objects | No top-level `scoring_algorithm_version` (each `pair_score` carries `algorithm_version`, required); **no `stats` anywhere**; `linear_rgb_median`/`normalized_linear_rgb_median` are `RgbPayload` = anyOf(array \| `{r,g,b}` \| string) and both are **required**; pair scores require any of `score`/`similarity`/`distance` | Generated client sends algorithm version per score (tests assert this). `stats` cannot be sent through the generated client until upstream documents it — **regression vs today's upload**, recorded as a gap. Pinned by `testMeasurementUploadSchemaOmitsStatsAndTopLevelAlgorithmVersion` |
| 6 | Measurement upload response | Unspecified (app accepted any 2xx) | `200` + `{capture_id, measurement_count, pair_score_count}` | Generated client returns typed counts (asserted) |
| 7 | Judgment upload request | `{judgments: [{pair_id, judgment}]}`; judgments constrained to `match\|near_match\|no_match` (prose) | Same shape; `judgment` is a free-form string (no enum) | No action; app keeps sending prose values |
| 8 | Judgment upload response | Unspecified | `200` + `{capture_id, judgment_count}` | Typed counts asserted |
| 9 | Ranked results | "latest or aggregate ranked results with source colors, scores, labels, capture provenance, printer profile, and scoring algorithm version" | `RankedResults` documents only `schema_version` (enum `lps-ranked-results/v1`) + `sheet_id`. The wire JSON carries `results[]` with `rank`, `pair_id`, `source_colors`, `score` aggregates, `current_judgment`, observation/capture counts, `printer_profile`, etc. — all **undocumented** | Generated client types only the envelope; the surface is exposed (`getRankedResults`) for when upstream documents the payload. Gap pinned by `testRankedResultsSchemaDocumentsOnlyTheVersionedEnvelope` |
| 10 | Auth | `Authorization: Bearer <token>`, optional in dev | `bearerAuth` HTTP bearer security scheme on every `/api/v1` operation; API-token plug upstream | Generated client sends no implicit auth; `BearerAuthMiddleware` injects it (asserted) |
| 11 | Errors | Unspecified | `ApiErrorResponse` (`errors`: object or array with `detail`/`source.pointer`) for 401/404/422 | Typed `.unauthorized`/`.notFound`/`.unprocessableContent` cases (404 asserted) |

## Endpoint gaps to file upstream

1. **Manifest payload undocumented** — `patches`, `pairs`, `page`,
   `registration_markers`, `printer_profile`, `sheet_version`,
   `manifest_url`, `created_at` must be documented in `TestSheetManifest` for
   generated clients to consume them (upstream tests already assert them on
   the wire).
2. **`stats` dropped** — `MeasurementUploadRequest` has no
   `stats`; the iOS app currently computes and uploads
   `sample_count`/`clipping_fraction`/`mean`/`standard_deviation` per patch.
   Until documented, those data are silently lost through the generated
   client.
3. **Ranked-results payload undocumented** — the whole `results` array.
4. **Combinator+properties schemas are hostile to generators** —
   `CaptureRequest` and `PairScoreRequest` use sibling `anyOf` + `properties`,
   which most OpenAPI toolchains (including OpenAPIKit) cannot consume; prefer
   `oneOf` with refs or split schemas.
